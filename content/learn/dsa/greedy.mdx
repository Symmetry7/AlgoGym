## The idea

A **greedy** algorithm builds the answer one step at a time, always taking the choice that looks best right now and never going back. When it works, it's usually a sort followed by one pass, and far simpler than dynamic programming.

The catch: many tempting rules are wrong. Before trusting one, look for an **exchange argument**. Take any optimal answer and show you can swap in the greedy choice without making it worse. Then the greedy choice is safe, and the same argument applies to what's left.

## Intuition

<Figure src="/learn/dsa/greedy/earliest-end.svg" alt="Seven booking bars on a timeline. The four that end earliest without overlapping, 1–3, 3–6, 6–8 and 8–11, are highlighted; the others overlap them." />

Packing a day with meetings: whichever meeting you attend first, you'd like to be free again as soon as possible. So pick the one that ends earliest, then repeat with whatever starts after it. Picking the one that *starts* earliest can trap you in a long meeting that blocks three short ones.

## Worked example

*Hall Bookings* with requests `[540, 600], [570, 630], [600, 660], [630, 720]`. Sorted by end time the order is the same. Take 540–600 and the hall is free from 600. 570–630 starts at 570, too early: skip. 600–660 starts exactly at 600: take it, free from 660. 630–720 starts before 660: skip. The answer is **2**.

## Code

<CodeTabs>

```js
function maxBookings(requests) {
  const sorted = [...requests].sort((a, b) => a[1] - b[1]);
  let free = -Infinity, count = 0;
  for (const [start, end] of sorted) if (start >= free) { count++; free = end; }
  return count;
}
```

```python
def max_bookings(requests: list[list[int]]) -> int:
    free, count = float("-inf"), 0
    for start, end in sorted(requests, key=lambda r: r[1]):
        if start >= free:
            count += 1
            free = end
    return count
```

```cpp
int maxBookings(vector<vector<int>> requests) {
    sort(requests.begin(), requests.end(), [](auto& a, auto& b) { return a[1] < b[1]; });
    long long freeAt = LLONG_MIN;
    int count = 0;
    for (auto& r : requests) if (r[0] >= freeAt) { count++; freeAt = r[1]; }
    return count;
}
```

```java
int maxBookings(int[][] requests) {
    int[][] sorted = requests.clone();
    Arrays.sort(sorted, (a, b) -> Integer.compare(a[1], b[1]));
    long free = Long.MIN_VALUE;
    int count = 0;
    for (int[] r : sorted) if (r[0] >= free) { count++; free = r[1]; }
    return count;
}
```

## Complexity

| | |
| --- | --- |
| Time | Usually O(n log n) for the sort plus O(n) for the pass |
| Space | O(1) to O(n), depending on whether you sort a copy |

## Common mistakes

<Callout>

- **Trusting a rule because it passes the examples.** Earliest start and shortest first both look right and both fail on small cases.
- **Taking the biggest step every time.** In Stepping Stones, the longest jump can land on a dead end that a shorter jump avoids; track the farthest reach instead.
- **Off-by-one on touching intervals.** Decide whether `end == start` overlaps, and read the statement: in Hall Bookings it doesn't.

</Callout>
