## The idea

In a linked list, every node holds a value and a link to the next node. There's no "jump to position i": the only way to reach a node is to walk from the head. In exchange, inserting or removing a node is O(1) once you're standing next to it: just change one link.

Algogym problems store a list as arrays: `values[i]` is node `i`'s value and `next[i]` is the index of the node after it, or `-1` at the end. The techniques are the same as with node objects.

Two tools cover most linked-list problems:

- **Rewiring with a few pointers.** Reversal, removal and insertion keep track of `prev`, `cur` and the saved next node.
- **Two walkers at different speeds or with a gap.** Fast/slow pointers find the middle or a loop. A gap of k finds the k-th node from the end.

## Intuition

<Figure src="/learn/dsa/linked-lists/reverse-links.svg" alt="Four linked nodes 11, 22, 33, 44. Below, after three steps, 22 points back to 11 and 33 back to 22; prev is on 33 and cur is on 44, the last node still to turn around." />

Think of a treasure hunt where each clue says only where the next clue is. To run it backwards you don't need a new set of clues: walk forward, and at each clue cross out "go to the next" and write "go back to the previous". Save the old instruction before you cross it out, or you'll never find the next clue.

## Worked example

*Relay Reversal* reverses `11 → 22 → 33 → 44`. Start with `prev = -1` and `cur` on 11.

1. Save `ahead = 22`, point 11 back to `-1`, then move: `prev = 11`, `cur = 22`.
2. Save `ahead = 33`, point 22 back to 11. Now `prev = 22`, `cur = 33`.
3. Save `ahead = 44`, point 33 back to 22. Now `prev = 33`, `cur = 44`.
4. Save `ahead = -1`, point 44 back to 33. Now `prev = 44`, `cur = -1`: stop.

The new head is `prev`, and walking from it gives **44, 33, 22, 11**. No node was copied; four links were turned around.

## Code

<CodeTabs>

```js
// Reverses the list in place and returns the new head.
function reverse(next, head) {
  let prev = -1;
  let cur = head;
  while (cur !== -1) {
    const ahead = next[cur];
    next[cur] = prev;
    prev = cur;
    cur = ahead;
  }
  return prev;
}
```

```python
def reverse(next: list[int], head: int) -> int:
    prev, cur = -1, head
    while cur != -1:
        ahead = next[cur]
        next[cur] = prev
        prev, cur = cur, ahead
    return prev
```

## Complexity

| | |
| --- | --- |
| Time | O(n) for one walk; fast/slow pointers are still O(n) |
| Space | O(1): a few pointers, no copy of the list |

## Common mistakes

<Callout>

- **Losing the rest of the list.** Save `next[cur]` before you change it.
- **Stepping past the end.** Before `fast = next[next[fast]]`, check that both `fast` and `next[fast]` exist.
- **Forgetting the head.** Removing the first node has no node before it; handle that case (or add a dummy node in front).
- **Returning the meeting point as the loop start.** Floyd's walkers meet somewhere inside the loop; a second walk from the head finds where it begins.

</Callout>
