## The idea

An array is a row of values you can reach by index in O(1). Most array questions can be answered in **one pass** if you decide up front what to carry from one index to the next: a running count, a running total, the best answer so far. Questions about many ranges get a second tool, **prefix sums**: precompute running totals once, then answer each range with one subtraction.

## Intuition

<Figure src="/learn/dsa/arrays-and-strings/one-pass.webp" alt="A row of eight cells scanned left to right; a small box under the scan pointer holds two counters, current and best, updated at each cell." />

Think of reading a bank statement line by line. You never re-read earlier lines; you keep the balance in your head and update it. If someone then asks "how much did I spend between the 3rd and the 9th?", you don't add those lines up again: you subtract the balance before the 3rd from the balance after the 9th.

## Worked example

Count the **record days** in `[21, 19, 24, 24, 27, 22, 30]`: days whose temperature is strictly higher than every earlier day.

Carry one value, `hottest`, the maximum seen so far. Day 0 (21) is a record because nothing came before it. 19 is not above 21. 24 is, so `hottest` becomes 24. The next 24 only ties it. 27 and later 30 each beat the running maximum. That is **4** records, found in a single pass with one extra variable.

The same shape solves *Quiet Hours*: carry the current run and the best run. *Range Totals* needs the other tool: build `prefix` once, then each question is `prefix[r + 1] − prefix[l]`.

## Code

<CodeTabs>

```js
function recordDays(temps) {
  let hottest = -Infinity;
  let records = 0;
  for (const t of temps) {
    if (t > hottest) {
      records++;
      hottest = t;
    }
  }
  return records;
}
```


## Complexity

| | |
| --- | --- |
| Time | O(n) for one pass; O(n + q) for n values and q range questions with prefix sums |
| Space | O(1) for running state; O(n) for a prefix array |

## Common mistakes

<Callout>

- **Starting the best value at 0.** If every value can be negative, start from the first element (or −∞) instead.
- **Off by one in prefix sums.** With `prefix[0] = 0`, the range `[l, r]` is `prefix[r + 1] − prefix[l]`, not `prefix[r] − prefix[l]`.
- **Forgetting the last group.** When you build output while scanning (as in run-length compression), the group still open at the end has to be written after the loop.

</Callout>
