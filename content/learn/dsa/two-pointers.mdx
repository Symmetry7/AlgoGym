## The idea

Many questions ask about **pairs**: two values that add up to something, two ends that match, two walls that hold the most water. Checking every pair is O(n²). With **two pointers**, usually one at each end of a sorted array or one in each of two lists, every step lets you discard a candidate for good, so the whole search takes O(n).

## Intuition

<Figure src="/learn/dsa/two-pointers/closing-in.svg" alt="A sorted row of numbers with arrows at both ends moving toward each other; crossed-out cells show values ruled out at each step." />

Two people search a sorted bookshelf for two books whose page counts add up to 500, one starting at the thinnest book and one at the thickest. If the pair is too short, the thin-end reader moves on: that thin book can't reach 500 with anything thicker than the thickest. If it's too long, the thick-end reader moves inwards. Neither of them ever has to go back.

## Worked example

Is there a pair in `[1, 2, 4, 5, 7, 11]` that adds up to **10**?

Start with `lo` on 1 and `hi` on 11. Their sum, 12, is too big, and since 1 is the smallest value left, 11 can't be part of any answer. Discard it. Now 1 + 7 = 8 is too small, and 7 is the largest value left, so 1 is out. Continuing (2 + 7 = 9, 4 + 7 = 11, 4 + 5 = 9), the pointers meet without finding 10. The answer is **no**, after 5 steps instead of 15 pair checks.

The same reasoning powers *Pair Budget*, where one comparison counts many pairs at once, and *Widest Tank*, where you always discard the shorter wall.

## Code

<CodeTabs>

```js
function hasPairWithSum(sortedValues, target) {
  let lo = 0;
  let hi = sortedValues.length - 1;
  while (lo < hi) {
    const sum = sortedValues[lo] + sortedValues[hi];
    if (sum === target) return true;
    if (sum < target) lo++;
    else hi--;
  }
  return false;
}
```

```python
def has_pair_with_sum(sorted_values: list[int], target: int) -> bool:
    lo, hi = 0, len(sorted_values) - 1
    while lo < hi:
        total = sorted_values[lo] + sorted_values[hi]
        if total == target:
            return True
        if total < target:
            lo += 1
        else:
            hi -= 1
    return False
```

## Complexity

| | |
| --- | --- |
| Time | O(n): each step moves one pointer, and they meet after at most n − 1 steps |
| Space | O(1) |

## Common mistakes

<Callout>

- **Using two pointers on unsorted data.** Discarding a value relies on order. Sort first, or use a hash map instead.
- **Moving the wrong pointer.** Move the side that can't be part of any better answer: the smaller sum's low end, or the shorter wall.
- **Overflow in the sum.** Two values near 2 × 10^9 overflow a 32-bit integer; add them in 64 bits.

</Callout>
